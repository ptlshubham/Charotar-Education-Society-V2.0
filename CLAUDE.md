# CLAUDE.md

Behavioral guidelines to reduce common LLM coding mistakes. Merge with project-specific instructions as needed.

**Tradeoff:** These guidelines bias toward caution over speed. For trivial tasks, use judgment.

## 1. Think Before Coding

**Don't assume. Don't hide confusion. Surface tradeoffs.**

Before implementing:
- State your assumptions explicitly. If uncertain, ask.
- If multiple interpretations exist, present them - don't pick silently.
- If a simpler approach exists, say so. Push back when warranted.
- If something is unclear, stop. Name what's confusing. Ask.

## 2. Simplicity First

**Minimum code that solves the problem. Nothing speculative.**

- No features beyond what was asked.
- No abstractions for single-use code.
- No "flexibility" or "configurability" that wasn't requested.
- If you write 200 lines and it could be 50, rewrite it.

## 3. Surgical Changes

**Touch only what you must. Clean up only your own mess.**

- Don't "improve" adjacent code, comments, or formatting.
- Don't refactor things that aren't broken.
- Remove imports/variables/functions that YOUR changes made unused.
- If you notice unrelated dead code, mention it - don't delete it.

The test: Every changed line should trace directly to the user's request.

## 4. Goal-Driven Execution

**Define success criteria. Loop until verified.** For multi-step tasks, state a brief plan with a verification step per item.

## 5. Project Standards

**The normative standard for all ZarklyX repos is `ENGINEERING_SOP.md` in the ZarklyX-Frontend-Portal repo.** Read it before writing code. Where it conflicts with existing code, the existing code is debt.

### Website quick reference (Angular 21, SSR + prerender, Tailwind 4)

**This repo is NOT the Portal.** Different Angular version, different design system, no KTUI/Metronic, no ApexCharts, SSR instead of pure SPA. **Never copy files from the Portal into this repo** — `core/helpers/error.interceptor.ts`, `core/guards/auth.guard.ts`, and `app/environments/environment.ts` are already dead Portal copies wired to nothing (see traps below).

**Paths & naming** — Angular 20+ style, **no `.component` suffix**:
```
src/app/pages/<section>/<sub-page>/<page>.{ts,html,scss}     class Blogs, NewsDetails
src/app/core/{services,interceptors,resolvers,guards}/
src/app/layouts/{header,footer,main-layout,ai-assistant,...}/
```
Section shells hold `<router-outlet />`; multi-section landing pages use an `index/` folder composing sibling section components. Every route is `loadComponent` lazy.

**Components MUST**
- use signals — `signal()`, `computed()`, `inject()` (see `pages/blogs/blogs.ts` as the reference)
- set `changeDetection: ChangeDetectionStrategy.OnPush` (currently used zero times repo-wide; new code still sets it)
- guard **every** `window` / `document` / `localStorage` / `navigator` access with `isPlatformBrowser(inject(PLATFORM_ID))` or `afterNextRender()`
- never gate app-wide UI on a single `navigator.*` read (`navigator.onLine` misreports on iOS cold load)

**SEO** — the most deliberately engineered part of this repo; don't work around it:
- Meta comes from super admin via `seoResolver`: `{ path: 'about', ...seo('about'), loadComponent: ... }`
- Precedence is `override > admin page entry > sitewide default`; blank values **remove** a tag
- `index.html` meta are documented **fallbacks only** — never hardcode page meta there
- The transfer cache is deliberately bypassed for the SEO endpoint; `withFetch()` is mandatory (the XHR shim never settles under Node)
- Adding a route requires: an entry in `app.routes.server.ts` with its render mode, **and** an entry in `src/app/shared/site-links.json` (single source for `sitemap.xml`, `llms.txt`, and the HTML sitemap page — generated by `scripts/generate-site-files.mjs`)

**Styling** — Tailwind v4 CSS-first. Brand tokens live in the `@theme` block in `src/tailwind.css`. Never hardcode brand hex in component styles; `.primary-btn`'s `#3BAEA9` has already drifted from `--color-main: #3DAFA9`.

**Services** — `ResourcesService` is the data-access facade. New methods MUST use `http.get<T>()` generics and shared models in `shared/models/`, not untyped `Observable<Object>` with a locally re-declared interface at each call site. Use `inject()` + 2-space indent (the `constructor(public http)` + 4-space files are the outliers).

**Known traps in this repo** (SOP §12): hosting target is self-contradictory — `angular.json` says `outputMode: "server"` with an Express entry while `public/.htaccess` and `app.routes.server.ts` comments assume static Apache; resolve this before changing render modes. `environment.production.ts` lacks the `firebase`/`google` blocks that `environment.ts` has, so code touching them compiles locally and breaks in prod. Newsroom is half-landed (`newsroom.html` is `<app-section-coming-soon/>` while a complete `news-details` page exists and the URL ships in `sitemap.xml`). `support/tutorials/:id` prerenders hardcoded ids 1–6. Prod budgets are disabled (5mb warn == 5mb error). All 34 `.spec.ts` are CLI stubs and `app.spec.ts` cannot pass — the suite is never run. Prettier is configured but has no `format` script.

**Branches:** `feat/…` / `fix/…` cut from `development`, ≤3 days, squash-merged. Do not use or extend personal branches (`Shubham`, `prarthan`).
